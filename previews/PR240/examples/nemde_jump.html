NEMDE as a JuMP model ​

The formulation overview introduces the full model. This page turns a deliberately reduced subset into running code: a JuMP model of a small market, solved with HiGHS. The market data is a PowerSystems.jl System, and the model reads its energy data through PSY's getters. The next page builds the energy part of this model with PowerSimulations.jl from the same System.

Example scope

This teaching model omits scheduled consumption, batteries, regulation FCAS scaling, fast-start profiles and price processing. Its piecewise loss curve is a toy approximation. See the formulation overview for the wider market formulation.

The toy market ​

Two regions joined by one interconnector with losses. COAL1 (thermal) and WIND1 (semi-scheduled, with a forecast UIGF) sit in NSW1; GAS1 (thermal) sits in VIC1. Both thermal units also offer RAISE6SEC FCAS. Three generic constraints complete the market: a stability limit on COAL1 and one RAISE6SEC requirement per region. A single 5-minute dispatch interval is cleared.

The market is built once, as the System returned by toy_system. Each generator carries its offer as a cost curve and its dispatch envelope as its active power limits, and each region has an Area, a bus and a load. Initial output, ramp rates, FCAS offers, generic constraints and loss parameters are not stock PSY fields for this toy, so they stay plain Julia data keyed by unit name.

region_colors = Dict(n => c for (n, c) in zip(unit_names, Makie.wong_colors()))

function merit_order(sys, region_name)
    steps = [(name = n, b = b) for n in units_in(sys, region_name) for b in offer_bids(sys, n)]
    sort!(steps; by = s -> price(s.b))
    return steps
end

function plot_merit_order!(ax, sys, market, region_name, region_colors; cleared = nothing, clearing_price = nothing)
    left = 0.0
    used = Dict(n => availability(find_unit(market, n)) for n in units_in(sys, region_name))
    for s in merit_order(sys, region_name)
        usable = min(quantity(s.b), used[s.name])
        used[s.name] -= usable
        height = max(price(s.b), 3.0)
        color = region_colors[s.name]
        poly!(
            ax, Rect2f(left, 0.0, usable, height);
            color = (color, 0.8), strokecolor = color, strokewidth = 1,
        )
        if usable < quantity(s.b)
            poly!(
                ax, Rect2f(left + usable, 0.0, quantity(s.b) - usable, height);
                color = (color, 0.15), strokecolor = color, strokewidth = 1, linestyle = :dash,
            )
        end
        left += quantity(s.b)
    end
    isnothing(cleared) || vlines!(ax, cleared; color = :white, linestyle = :dash)
    isnothing(clearing_price) || hlines!(ax, clearing_price; color = :tomato, linestyle = :dot)
    return nothing
end

function merit_order_legend!(fig, position, names, region_colors)

end

Energy: bands, envelopes and regional balance ​

The decision variables are the MW cleared in each band of each offer, bounded by the band quantity. The bands are read from each generator's cost curve. A unit's dispatch is the sum of its bands, and the objective is the offer cost over the interval of   hours.

The interconnector and its losses ​

The flow is a signed variable. The loss curve is linearised on the breakpoints: the flow is the first breakpoint plus the flow allocated to each segment, the loss is the loss at the first breakpoint plus each segment's slope times its flow, and a binary per segment boundary forces the segments to fill in order, so the solved loss follows the curve. The loss of the segment that brackets zero flow is subtracted, so the linearised curve loses nothing at zero flow, as in the package's loss model. The flow limit and the exporting region come from the AreaInterchange.

julia
ic = market.interconnector
segments = linearised_losses(ic)
from = PSY.get_name(PSY.get_from_area(interconnector(sys)))
max_flow = flow_limit(sys)

@variable(model, flow)
@variable(model, 0 <= segment_flow[s in eachindex(segments)] <= segments[s].to_mw - segments[s].from_mw)
@variable(model, filled[s in 1:(length(segments) - 1)], Bin)
@expression(model, loss, loss_at(ic, ic.breakpoints[1]) - zero_flow_chord_loss(ic) + sum(segments[s].slope * segment_flow[s] for s in eachindex(segments)))

@constraint(model, flow_definition, flow == ic.breakpoints[1] + sum(segment_flow))
@constraint(model, segment_full[s in 1:(length(segments) - 1)], segment_flow[s] >= (segments[s].to_mw - segments[s].from_mw) * filled[s])
@constraint(model, segment_next[s in 1:(length(segments) - 1)], segment_flow[s + 1] <= (segments[s + 1].to_mw - segments[s + 1].from_mw) * filled[s])
@constraint(model, flow_limit_up, flow <= max_flow)
@constraint(model, flow_limit_down, flow >= -max_flow)

Regional balance and prices ​

Each region supplies its demand plus the flow it exports plus its share of the losses. The regional price is the dual of this row: the cost of one more MW of demand there.

Solving ​

The segment binaries make this a small MILP. NEMDE prices come from the LP, so after the first solve the binaries are fixed at their solution and the LP is solved again to read the duals. Duals are per MW per interval; dividing by gives $/MWh.

julia
function solve!(model)
    optimize!(model)
    @assert termination_status(model) == OPTIMAL
    undo = fix_discrete_variables(model)
    optimize!(model)
    @assert termination_status(model) == OPTIMAL
    result = (;
        dispatch = Dict(Symbol(n) => value(model[:dispatch][n]) for n in unit_names),
        flow = value(model[:flow]),
        loss = value(model[:loss]),
        price = Dict(r => dual(model[:balance][r]) / INTERVAL_H for r in regions),
        objective = objective_value(model),
        raise = haskey(model, :raise) ? Dict(Symbol(n) => value(model[:raise][n]) for n in fcas_names(market)) : nothing,
        generic = haskey(model, :generic) ? Dict(n => dual(c) / INTERVAL_H for (n, c) in model[:generic]) : nothing,
        violation = haskey(model, :violation) ? Dict(n => value(v) for (n, v) in model[:violation]) : nothing,
    )
    undo()
    return result
end

FCAS: the trapezium ​

Each unit offering RAISE6SEC gets a capacity variable, the sum of its FCAS bands, and two joint rows that keep that capacity inside the unit's trapezium at its energy dispatch, so energy and FCAS compete for the same MW. The FCAS offer cost joins the objective. The FCAS offers are plain data keyed by unit name.

julia
fnames = fcas_names(market)

@variable(model, 0 <= raise[n in fnames] <= max_avail(trapezium(market, n)))

@constraint(model, raise_definition[n in fnames], raise[n] == sum(raise_cleared[n, j] for j in eachindex(fcas_bids(market, n))))

@expression(model, fcas_cost, sum(price(b) * raise_cleared[n, j] * INTERVAL_H for n in fnames for (j, b) in enumerate(fcas_bids(market, n))))
set_objective_function(model, objective_function(model) + fcas_cost)

Generic constraints ​

Both the RAISE6SEC requirements and the network limit are generic constraints: a linear combination of unit energy, unit FCAS and interconnector flow, a sense and a right-hand side. Each toy constraint carries a violation variable, paid at its penalty factor times the Market Price Cap. This follows the violation-priority principle in AEMO's Schedule of Constraint Violation Penalty Factors (§1, pp. 3-4). For each independent, unit-coefficient FCAS requirement here, the dual divided by the interval duration gives its FCAS price.

julia
model[:generic] = Dict{String, ConstraintRef}()
model[:violation] = Dict{String, VariableRef}()

function term_variable(model, t::Term)
    t.kind == :energy && return model[:dispatch][String(t.id)]
    t.kind == :raise6 && return model[:raise][String(t.id)]
    return model[:flow]
end

function add_generic_constraint!(model, gc::LinearConstraint)
    lhs = sum(t.factor * term_variable(model, t) for t in gc.terms)
    violation = @variable(model, lower_bound = 0, base_name = "violation_$(gc.name)")
    model[:generic][gc.name] = if gc.sense == :LE
        @constraint(model, lhs - violation <= gc.rhs)
    else
        @constraint(model, lhs + violation >= gc.rhs)
    end
    model[:violation][gc.name] = violation
    set_objective_function(model, objective_function(model) + gc.weight * MARKET_PRICE_CAP * INTERVAL_H * violation)
    return nothing
end

Co-optimisation changes the energy outcome. NSW1 has to hold 40 MW of RAISE6SEC on the coal unit; at 400 MW of energy the trapezium only lets it offer 30 MW, so energy is pushed down until the joint row is satisfied. That removes cheap export, the interconnector comes off its limit and the gap between the two regional prices shrinks to the cost of marginal losses. The FCAS price is not the $8/MW/h of the marginal FCAS offer: it also contains the energy the coal unit gives up.

    lines!(ax, flows, loss_at.(Ref(ic), flows); label = "quadratic loss")
    bp = ic.breakpoints
    lines!(ax, bp, loss_at.(Ref(ic), bp) .- zero_flow_chord_loss(ic); linestyle = :dash, label = "linearisation")
    for (label, r, marker) in (("energy only", energy_only, :diamond), ("with FCAS and limit", constrained, :circle))
        scatter!(ax, r.flow, r.loss; markersize = 14, marker, label)
    end
    axislegend(ax; position = :ct)
    fig
end
