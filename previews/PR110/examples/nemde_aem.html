Building it with AEM and AEMSim ​

The previous page solves an energy-only market using PowerSimulations.jl (PSI). This page includes FCAS, losses and generic constraints in the toy market of the JuMP model, using AustralianElectricityMarkets and AustralianElectricityMarketsSimulations. It then compares dispatch, flows and prices with the JuMP example.

References

The market rules behind each formulation are in AEMO's FCAS Model in NEMDE and Constraint Violation Penalty Factors; see References.

The interconnector's loss model ​

Interconnector losses are shared between the two regions. The toy loss model uses a quadratic curve with five linear segments.

julia

attach_loss_model!(sys, market);

Market data as time series ​

Energy offers, availability, telemetered ramp rates and metered initial output specify the unit's feasible dispatch for the interval. For NEMWEB data, set_market_bids! and set_unit_conditions! attach these inputs.

julia

attach_energy_data!(sys, market);

FCAS as a service ​

The thermal units offer RAISE6SEC. Each offer includes price bands and a trapezium describing the FCAS capacity available at each energy dispatch level.

julia
attach_fcas_data!(sys, market);

Generic constraints ​

Generic constraints impose linear limits on energy dispatch, FCAS enablement and interconnector flows. This example includes two regional FCAS requirements and a coal dispatch limit.

julia


attach_generic_constraints!(sys, market);

The derived NEMDE inputs ​

nem_system ends by deriving the inputs the run reads from the raw ones: the offers referred to the regional reference node, the effective FCAS trapeziums, the loss demand coefficients, the tie-break scales, the starting output of each unit, and the five-minute forecast windows. That stage has no public entry point, because nem_system always runs it; the toy calls the internal function directly on its hand-built System, which then runs the one interval T0.

Step 2: the template ​

template_nemde builds the data-free problem template: NEMDispatch for each dispatch device type, the regional balance with slacks, the interconnector losses, and one service model per FCAS service and per generic constraint. template_skipped_constraints reports, without changing sys, the constraints the run leaves out, and PSI.validate_template verifies the inputs and that the template models every participant when the model is built.

julia
template = template_nemde()
skipped = template_skipped_constraints(sys, template)
isempty(skipped)
true

Step 3: build and solve ​

AEMSim.NEMDispatchProblem prices the regional balance slacks and every penalty at one Market Price Cap, dated by the first interval.

julia
model_psi = PSI.DecisionModel(
    AEMSim.NEMDispatchProblem, template, sys;
    optimizer = optimizer_with_attributes(HiGHS.Optimizer, "output_flag" => false, "mip_rel_gap" => 0.0),
    initial_time = T0,
    name = "nemde_aem",
)
build_status = PSI.build!(model_psi; output_dir = mktempdir())

solve_status = PSI.solve!(model_psi)
InfrastructureSystems.Simulation.RunStatusModule.RunStatus.SUCCESSFULLY_FINALIZED = 0

Step 4: results, checked against the JuMP model ​

Variables are in MW. Duals are per unit of the system base and per interval, so dual / (BASE_POWER * INTERVAL_H) is $/MWh. FCAS prices come from read_fcas_prices, which sums the duals of the generic constraints that carry an FCAS requirement.

julia
results = PSI.OptimizationProblemResults(model_psi)
to_dollars_per_mwh(dual) = dual / (BASE_POWER * INTERVAL_H)

value_by_name(df) = Dict(Symbol(r.name) => r.value for r in eachrow(df))
psi_dispatch = merge(
    value_by_name(read_variable(results, "ActivePowerVariable__ThermalStandard")),
    value_by_name(read_variable(results, "ActivePowerVariable__RenewableDispatch")),

Elastic constraints ​

Constraint violations incur a penalty based on the constraint violation penalty factor and the Market Price Cap (AEMO, Schedule of Constraint Violation Penalty Factors, §1, pp. 3-4). This prioritises which limits to relax if the inputs conflict. The total violation in the toy solution is:

julia
slack_total
0.0

Nothing is violated in the toy market, so the solution equals the JuMP model of the JuMP model, which carries only the generic constraint violations.

From the toy to the real market ​

Everything above was assembled by hand to show the pieces. For real intervals:

  1. db = aem_connect() and populate(db, table, start, stop) cache the NEMWEB tables.

  2. nem_system(db, NEMDEConfiguration(); date_range) builds the populated System, including energy and FCAS offers, dispatch and energy limits, generic constraints and losses. It ends with the NEMDE input stage the toy called above, so the derived inputs and the five-minute forecast windows are already in place, and dispatch_intervals(sys) lists the intervals it can run.

  3. The run pre-flight checks run when the model is built, and template_skipped_constraints(sys, template) reports the constraints left out.

  4. Construct, build and run a PSI simulation of the dispatch intervals. nem_dispatch_sequence adds NEMDE's second, fast-start run to each interval when the System has a fast-start unit:

    julia
    steps = dispatch_intervals(sys)
template = template_nemde()
(; models, sequence) = nem_dispatch_sequence(
    AEMSim.NEMDispatchProblem, template, sys;
    optimizer = AEMSim.nemde_optimizer(), initial_time = first(steps),
)
simulation = PSI.Simulation(;
    name = "NEMDE", steps = length(steps), models, sequence,
    simulation_folder = mktempdir(), initial_time = first(steps),
)
PSI.build!(simulation; store_systems_in_results = false)
PSI.execute!(simulation)
results = PSI.get_decision_problem_results(PSI.SimulationResults(simulation), "dispatch")

  5. read_solved_interval(results, sys) and read_constraint_violations(results, sys) extract the solved quantities and constraint violations, and compare_intervals joins them with read_published_interval from the cache. Running NEMDE dispatch runs these steps on real intervals.

Validate the study inputs before solving. check_fcas_services(template, sys) verifies that every FCAS service has a corresponding model in the template, read_interconnector_loss_gaps(results, sys) after a solve verifies that each solved loss lies on the loss curve at the solved flow: its gap_mw column is zero.

Example scope

This tutorial solves a single interval with thermal and wind generation, one contingency FCAS service and a toy loss curve. It omits scheduled consumption, batteries, regulation FCAS scaling, fast-start profiles and price processing. See Fast-start dispatch and the formulation overview for those market concepts.
